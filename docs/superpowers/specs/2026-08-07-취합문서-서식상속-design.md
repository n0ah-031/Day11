## 1. 문제

취합 결과가 **원본 양식의 서식을 하나도 이어받지 않습니다.** 사용자가 배포본에서 받아온
실제 아웃풋(`merged.xlsx` 36행 × 9열)을 원본 양식과 대조한 결과입니다.

| 원본 양식 `2025년 대상 리스트` | merged.xlsx |
|---|---|
| 제목 `2025년 집중안전점검…` — `A1:H1` 병합 · 72pt 볼드 · 행높이 162 | 없음 |
| 작성 안내 행 `※ 2024.11.01…` — 36pt 볼드 | 없음 |
| 헤더 행 — 36pt 볼드 · 배경색 · 테두리 · 가운데 정렬 · 행높이 74.25 | 11pt 민무늬, 정렬·테두리·색 없음 |
| 데이터 행 — 36pt · 테두리 · 가운데 정렬 | 서식 없음 |
| 열너비 `A 16.2 · C 102.6 · D 27.2 · E 30.8 · F 40.8 · G 33.0 · H 53.2` | **지정 0개** (전부 기본 8.43) |
| 자동필터 `A4:H9` | 없음 |
| 숫자서식 — `개소` `0_);[Red](0)` · `점검일시` `mm-dd-yy` | 없음 → 날짜가 `2025-01-08 00:00:00`으로 표시됨 |
| 인쇄설정 — 용지맞춤 · 인쇄영역 `A1:H9` · 반복행 `$1:$4` | 없음 → 2쪽부터 헤더가 사라짐 |

원인은 [aggregate.py](../../../aggregate.py) `_write_block`이 `ws.cell(...).value`만 쓰는 것입니다.
**값만 옮기고 스타일은 읽지도 않습니다.** `write_report`도 같습니다.

### 용도

취합 결과를 받은 담당자는 ① **직접 분석·가공**(피벗·수식·필터)하고 ② **회신 관리·독촉**
(누가 냈고 무엇이 빠졌는지 확인)에 씁니다. 보고서용 미화는 용도가 아닙니다.

두 번째 용도에 지금 빈 곳이 있습니다 — 두 파일 어디에도 **"8개 중 2개가 통째로 빠졌다"**는
사실이 없습니다. 제외 사실은 화면과 stdout에만 있고, 파일만 받은 사람은 6개가 전부인 줄 압니다.

## 2. 목표 / 비목표

**목표**

1. A·B·C·D **네 모드 모두** 원본 양식의 서식을 이어받는다
2. 어떤 모드·어떤 시트든 최소한 헤더 강조·틀고정·자동필터·열너비는 갖는다
3. 두 아웃풋 파일 모두 **제출·취합·제외 현황**을 자기 안에 담는다
4. 서식 처리가 실패해도 **값은 반드시 나온다**

**비목표**

- 보고서용 미화(로고·색 테마 등). 원본 양식이 가진 것만 이어받는다
- 회신 받는 쪽 장치(조건부서식·유효성검사)의 이전
- 값 자체의 정규화(문자열 날짜 → 날짜 타입 변환 등). 별건이다

## 3. 서식 원천

### 규칙 1 — 이 시스템에서 만든 양식이 있으면 그것이 기준

F1 생성 양식·F6 등록 양식을 취합 화면에서 고른 경우, **그 양식 파일에서 서식을 캡처**하고
다수결하지 않는다. 양식이 정답이고 회신본은 사본이다.

지금 그 화면([ui/aggregate.html](../../../ui/aggregate.html) `#template-pick`)은
작성기준(`field_rules`)만 받아온다. **Storage에서 양식 xlsx도 받아오도록 붙인다**
(경로는 `form_download` 엔드포인트가 쓰는 것과 같다).

### 규칙 2 — 양식이 없으면 취합 대상 전 파일에서 항목별 최빈값

실측 근거 — 같은 양식의 회신본 8개(`sampledata/`)를 항목별로 비교했다.

| 항목 | 결과 |
|---|---|
| 제목 텍스트·병합·행높이 | **8/8 동일** |
| 헤더 글꼴·배경색·테두리·정렬 | **8/8 동일** |
| 컬럼별 숫자서식 | **8/8 동일** |
| 인쇄 반복행 `$1:$4` | **8/8 동일** |
| 열너비 | **3종** — 6개 `C:102.6` / 1개 `C:104.6` / 1개 `A:38.8·B:40.8` |
| 자동필터 범위 | 4종 — `A4:H63` · `H29` · `H9` · `H6` |
| 인쇄영역 | 4종 — `$A$1:$H$63` · `H29` · `H9` · `H6` |

두 가지가 여기서 나온다.

**진짜 서식은 이미 만장일치다.** 갈리는 것은 열너비 하나뿐이고 그것도 지사가 손으로 늘린
흔적이다(`A:38.8`은 한 지사만). 따라서 다수결은 **손댄 흔적을 걷어내고 원래 배포된 양식을
되찾는** 장치다.

**필터 범위·인쇄영역은 다수결 대상이 아니다.** 4종으로 갈린 이유는 서식 차이가 아니라
지사마다 **데이터 행 수가 다르기 때문**이다(`H63`·`H29`·`H9`·`H6`). 최빈값 `H63`을 쓰면
36행짜리 결과에 63행 필터가 걸린다. **재계산 대상**이다.

| 결정 방식 | 대상 |
|---|---|
| **항목별 최빈값** | 제목 블록 · 헤더 서식 · 데이터 셀 서식 · 열너비 · 컬럼별 숫자서식 · 용지 방향 · 반복행 |
| **재계산** | 자동필터 범위 · 인쇄영역 · 틀고정 |
| 동수일 때 | 파일명 오름차순 첫 번째 |

파일 단위로 대표 1개를 뽑지 않고 항목별로 세는 이유: 지사마다 손댄 곳이 다르면 파일 단위로는
"완전히 일치하는 그룹"이 잘게 부서진다. 항목별로 세면 각 항목이 원래 값으로 수렴한다.

### 컬럼 매칭은 위치가 아니라 헤더 이름으로

열너비·숫자서식은 **헤더 문자열로 맞춘다.** 위치로 맞추면 어느 파일이 컬럼을 하나 끼워
넣었을 때 그 뒤가 전부 밀린다. 양식과 회신본의 컬럼 수가 달라도 같은 이유로 이름 매칭이 맞다.

### 무엇을 기준 삼았는지 밝힌다

`취합 개요` 시트와 화면 안내에 한 줄 남긴다.

```
기준 서식: 등록 양식 '2025년 대상 리스트'                    ← 규칙 1
기준 서식: 취합 파일 8개의 공통 서식 (열너비는 6/8 다수)       ← 규칙 2
```

## 4. 출력 행 배치

제목 블록을 복원하므로 **헤더가 원본과 같은 행 번호에 놓인다.** `SheetData.header_row`가
원본의 실제 행 번호를 갖고 있어(판교지사 = 4) 제목·안내 행은 `1 ~ header_row-1`로 기계적으로
잘린다. 추측하지 않는다.

```
r1   [2025년 집중안전점검 … 자체점검 리스트]   ← A1:I1 병합 · 72pt · 행높이 162
r2   (빈 행, 원본 그대로)
r3   ※ 2024.11.01 …                          ← 36pt 볼드
r4   부서 | 지사 | 개소 | 위치 | …             ← 헤더: 볼드·배경색·테두리·가운데
r5~  대구 | 대구 | 2   | 본리네거리 | …          ← 데이터 서식 반복
```

부수 효과로 **인쇄 반복행 `$1:$4`가 계산 없이 그대로 옮겨간다.**

## 5. 상속 항목

| 옮긴다 | 방식 |
|---|---|
| 제목·안내 행 (`1 ~ header_row-1`) | 값·서식·병합·행높이 그대로. 병합은 열 오프셋만큼 밀고 **출력 열 수에 맞춰 넓힌다**(`A1:H1` → `A1:I1`) |
| 헤더 행 서식 | 폰트·채우기·테두리·정렬. 값은 `부서`(+`구분`) + 원본 헤더 |
| 데이터 행 서식 | 원본 **`header_row + 1`행**을 본떠 전 행에 적용 |
| 컬럼별 숫자서식 | 헤더 이름으로 매칭 |
| 열너비 | 헤더 이름으로 매칭. `부서`·`구분` 열은 값 길이에 맞춤 |
| 용지 방향 · 용지맞춤 · 반복행 | 그대로 |

| 안 옮긴다 | 이유 |
|---|---|
| 데이터 영역 병합 (`A5:A6` 지사·개소) | 취합은 병합 값을 각 행에 채우는 것이 맞다(HANDOFF §4에서 그렇게 고쳤다). 되살리면 그 수정이 무효가 된다 |
| 데이터 행높이 (85.5) | 사진을 넣으라고 높인 값이다. **이미지를 옮겨 붙인 행만** 원본 높이를 따르고 나머지는 기본 |
| 조건부서식 · 유효성검사 | 회신 받는 쪽 장치라 취합 결과에는 뜻이 없다 |

## 6. 모드별 상속

| 모드 | 출력 시트 | 서식 원천 | 열 오프셋 | 제목 블록 |
|---|---|---|---|---|
| **A** 원본 보존형 | `{부서}_{원본시트명}` — 파일마다 | **그 파일 자신의 시트** (규칙 1·2를 타지 않는다 — 아래) | 0칸 | 복원 |
| **B** 시트명 누적 | 원본 시트명 | 규칙 1 → 규칙 2 | 1칸 (`부서`) | 복원 |
| **C** 그룹 누적 | 그룹명 | 규칙 1 → 규칙 2 | 2칸 (`구분`·`부서`) | 복원 |
| **D** B + 요약 | B와 동일 + `종합요약` | 데이터 시트는 B와 같음 | 1칸 | 복원 |
| 헤더불일치 분리 | `{시트명}_헤더불일치` | 분리된 그 파일의 시트 | 2칸 (`부서`·`시트`) | 복원 |

**모드 A는 §3의 서식 원천 규칙을 타지 않는다.** 양식을 골랐더라도 각 시트는 그 시트를 만든
파일 자신의 서식을 쓴다 — 모드 A의 목적이 원본 보존이고, 여러 파일이 한 시트에 쌓이지 않아
서식이 섞일 일이 없기 때문이다. 다수결로 남의 열너비를 씌우면 원본 보존이 아니게 된다.

> **모드 A의 동작이 하나 바뀐다.** 지금은 헤더를 1행으로 당겨 쓰는데([aggregate.py](../../../aggregate.py)
> `synthesize` 모드 A 분기), 제목 블록을 복원하면 헤더가 원본 자리로 돌아간다.
> 이미지 보정(`_row_offset`)도 그만큼 0이 되어 단순해진다.

### 원본에 대응 셀이 없는 시트

세 곳뿐이고 여기서도 맨 표로 떨어뜨리지 않는다.

| 시트 | 상속되는 것 | 상속 못 하는 것 |
|---|---|---|
| `종합요약` (모드 D) | 헤더 서식·글꼴·테두리 — 기준 서식에서 캡처한 것을 재사용 | 열너비·컬럼별 숫자서식 |
| `총괄표(전개)` 피벗 | 제목 블록 · 헤더 서식 · 데이터 셀 서식 | 컬럼별 숫자서식·열너비 (월×지표를 눕혀 221열이라 1:1 대응이 없다) |
| 기준 서식을 못 만들었을 때 | — | 전부. 아래 기본서식으로 채운다 |

### 기본서식

위 표의 "상속 못 하는 것"과 기준 서식 캡처가 실패한 경우에 채우는 값. 지어낸 스타일이 아니라
**같은 결과 문서의 서식 어휘를 재사용**해 한 문서처럼 보이게 한다.

| 항목 | 값 |
|---|---|
| 헤더 행 | 기준 서식에서 캡처한 헤더 서식. 캡처 실패 시에만 볼드 + 회색 배경 + 얇은 테두리 + 가운데 |
| 틀고정 | 헤더 행 바로 아래 |
| 자동필터 | 헤더 행 전체 |
| 열너비 | 값 길이에 맞춤 (상한 60자) |
| 숫자서식 | 값 타입 기준 — 날짜는 기준 서식에서 본 날짜서식, 없으면 `yyyy-mm-dd` |

## 7. 취합 개요 시트

두 파일 **모두** 맨 앞(index 0)에 넣는다. 어느 파일만 전달되어도 누락을 놓치지 않는다.

```
취합 일시 · 모드 · 기준 서식
제출 8 · 취합 6 · 제외 2 · 결과 36행

부서        파일명                    판정   취합   행수   사유
대구        …리스트(대구).xlsx          정상   ○      2
중앙지사    …리스트(중앙지사).xlsx      이상   ✕      —     필수값 누락 8건
분당사업소  …리스트(분당사업소).xlsx    이상   ✕      —     필수값 누락 1건
판교지사    …(양식)_판교지사.xlsx       이상   ○      2     합계행 2행 제외
```

`부서`·`판정`·`행수`는 `UploadedFile`에서, 제외 여부는 `selected` 목록에서, 사유는 `issues`를
등급별로 집계해 만든다. 서버가 이미 `payload["excluded_files"]`로 같은 정보를 계산하지만
**CLI에서도 나와야 하므로 엔진 쪽에서 만든다.**

원본 양식과 무관한 문서라 상속 대상이 아니다. §6의 **기본서식**만 입힌다 — 헤더 강조 ·

## 9. 코드 구조

**새 파일 `xlsx_format.py`.** [aggregate.py](../../../aggregate.py)는 이미 70KB이고, 서식
캡처·적용은 취합 판정과 완전히 다른 관심사다. 인터페이스는 넷이다.

```python
capture(path, sheet_name, header_row) -> FormatTemplate | None
    # 원본 xlsx 하나에서 서식만 읽는다. 못 열면 None (예외를 밖으로 내지 않는다)

consensus(templates) -> FormatTemplate
    # 항목별 최빈값. 동수는 입력 순서(파일명 오름차순) 첫 번째

apply(ws, template, col_offset, extra_headers, data_rows, image_rows)
    # 출력 시트에 입힌다. 필터·인쇄영역·틀고정은 여기서 재계산

overview_sheet(wb, index, run) -> None
    # 취합 개요 시트를 만든다. merged·report 양쪽이 같은 함수를 쓴다
```

`FormatTemplate`은 dataclass — `title_block`(값·서식·병합·행높이) · `header_style` ·
`data_style` · `widths: dict[헤더명, float]` · `number_formats: dict[헤더명, str]` ·
`page_setup` · `source_label`.

### 호출 지점 변경

`synthesize`가 개요 시트를 만들려면 **제외된 파일까지** 알아야 하는데 지금은 `selected`만
받는다. 그리고 개요에 실을 결과 행수는 `synthesize`만 안다. 반환값을 3-튜플로 넓힌다.

```python
wb, notes, overview = synthesize(selected, mode, group_map, summary_cols,
                                 all_files=files, template_path=None)
write_report(files, report_path, overview=overview)
```

호출 지점은 [server.py](../../../server.py)와 `aggregate.main()` 둘뿐이다.

**`write_report`를 `synthesize` 뒤로 옮긴다.** 지금은 server.py에서 리포트를 먼저 쓰므로
결과 행수·기준 서식을 모른다. `write_report`가 쓰는 `uf.issues`·`uf.fixes`는 `review_stage1`이
확정하고 `preprocess`·`synthesize`가 건드리지 않으므로 순서를 바꿔도 내용은 같다 —
**테스트로 고정한다.**

## 10. 실패 처리

서식은 **부가물이다. 실패해도 값은 나온다.**

| 상황 | 처리 |
|---|---|
| 원본 파일을 다시 열 수 없음 | `capture`가 `None`. 그 파일은 다수결에서 빠진다 |
| 전 파일 캡처 실패 | 기본서식으로 진행. 개요에 `기준 서식: 없음(기본서식 적용)`을 적는다 |
| 양식 파일을 Storage에서 못 받음 | 규칙 2로 내려가고 개요에 밝힌다 |
| `apply` 중 예외 | 그 시트만 서식 없이 두고 진행. 취합을 실패시키지 않는다 |

## 11. 테스트

[test_aggregate.py](../../../test_aggregate.py)에 시나리오를 더한다.

1. **서식 상속** — 제목 병합·헤더 채우기·열너비·숫자서식·자동필터 범위·인쇄 반복행이 결과에 옮겨진다
2. **열 오프셋** — 모드 B는 1칸, 모드 C는 2칸. 열너비가 헤더 이름으로 따라간다
3. **모드 A** — 파일마다 자기 서식. 헤더가 원본 행 번호에 놓인다
4. **다수결** — 열너비가 갈린 파일 3개를 넣어 최빈값이 이긴다. 필터 범위는 최빈값이 아니라 결과 행수로 재계산된다
5. **양식 우선** — 양식을 주면 다수결하지 않고 양식 서식이 쓰인다
6. **개요 시트** — 제출·취합·제외 수와 제외 사유가 맞다. 두 파일 모두에 있다
7. **폴백** — 원본을 못 열어도 값은 전부 나오고 기본서식이 붙는다
8. **리포트 순서** — `write_report`를 뒤로 옮겨도 오류·자동교정 내용이 같다

[test_server.py](../../../test_server.py)에 1개 — 다운로드된 `merged.xlsx`에 서식과 개요
시트가 있다.

**실측** — `sampledata` 8개로 A·B·C·D 네 모드를 돌려 파일을 열어본다. 네트워크·API 키 없이
돈다(`--no-ai`).

## 12. 범위 밖

사용자가 보내준 `merged.xlsx`의 `부서` 컬럼이 `2025년도 집중안전점검 지열지점…`으로
**파일명 전체**다. 업로드 화면의 부서명 추천 칩을 고르면 `대구`·`판교지사`로 들어간다
(HANDOFF §6 '실제 파일로 쓸 때 반드시 지정할 것'). 서식과 별개 문제라 이번 설계에 넣지 않았다.
